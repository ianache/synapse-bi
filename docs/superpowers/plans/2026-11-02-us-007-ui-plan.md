# US-007 CDC UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the approved desktop and mobile CDC pipeline, execution, version lineage, and failure views using the existing Synapse BI application and US-007 APIs.

**Architecture:** Add a focused CDC workspace routed under `/datasets/preparacion-cdc`, reusing `SynapseShell`, source and dataset repositories, and the authenticated API pattern. Add typed preparation API access and responsive React views for pipeline setup, run history/detail, and prepared version history/current state. Use API results only; preserve the approved empty states.

**Tech Stack:** React 19, TypeScript, Vite, existing Synapse BI design-system components and CSS, existing FastAPI US-007 endpoints.

**Spec:** `docs/superpowers/specs/2026-11-02-us-007-backend-cdc-design.md`; approved screens in `docs/ux/us-007/README.md` and linked Google Stitch HTML/screenshots.

## Global Constraints

- Follow the approved Stitch composition, hierarchy, navigation, typography, palette, spacing, density, iconography, and states for desktop and mobile.
- Reuse the existing application shell and API authentication. Do not hard-code mockup rows, counters, permissions, timestamps, or state.
- API scopes remain authoritative: configuration and retry need `datasets:write` plus `sources:read`; reads use `datasets:read`.
- Technical failure details appear only when returned to an authorized Data Engineering principal; never expose raw payloads or credentials.
- The manual retry API requires corrected events; the user approved a JSON event editor in the run detail on 2026-11-02. Polling retries submit no body.
- Do not claim visual conformance until functional checks and desktop/mobile screenshot comparison are documented.

## Review Focus

- Empty API collections render actual empty states without invented rows or counts.
- Failed requests and expired/insufficient authorization show recoverable, safe errors.
- Mobile navigation, drawer, tabs, tables, and action targets remain usable at the approved narrow viewport.
- Consumer run details never render sanitized technical errors that the API omits.
- Manual-origin retries validate a non-empty JSON array of event objects before submission.
